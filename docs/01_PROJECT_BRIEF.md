# PROJECT_BRIEF

## 1. サイト概要

個人向け家計簿Webアプリ。

収入・支出・残高・月ごとのお金の流れを、できるだけ少ない操作で把握できるようにする。

## 2. 制作目的

実装速度ではなく、最終的なサイト品質を最大化する。

特に以下を重視する。

- 視認性
- 操作性
- 情報整理
- レスポンシブ対応

## 3. 想定ユーザー

- 20代後半〜30代の個人ユーザー
- 家計管理を簡単に続けたい人
- 細かい会計知識を持たない一般ユーザー

## 4. 主要ユーザー行動

- 現在の収入・支出・残高を把握する
- 収入または支出を入力する
- 過去の収支を確認する
- 月単位のお金の流れを確認する
- 必要な設定を変更する

単一の「最重要ユーザー行動」と、その優先順位はTBD。

## 5. 必要ページ

- ダッシュボード
- 収支一覧
- 収支入力
- 月次レポート
- 設定

詳細は `03_SITEMAP.md` を参照する。

## 6. デザイン方向性

参考サイトの役割を以下のように分ける。

- Stripe Dashboard：情報設計
- Linear：UI密度・一貫性
- Apple：視覚階層・情報の引き算

写真を原則使用せず、数字・タイポグラフィ・チャート・余白を主要な視覚要素とする。

詳細は `04_DESIGN_DIRECTION.md` を参照する。

## 7. 制作上の制約

- 中小規模の新規Webアプリとして制作する
- 確定した5ページ以外を追加しない
- 不要な機能を追加しない
- 将来を想定した過剰設計をしない
- サイト本文・コピーを勝手に作らない
- 提供されていない事実・データを作らない
- 未決定事項を推測で補完しない
- 未決定事項はTBDとして維持する
- Desktop / Tablet / Mobileを対象とする
- アクセシビリティを考慮する

## 8. 提供済み素材

- ロゴ：なし
- 写真・画像素材：なし
- ロゴ部分：仮プレースホルダーを使用
- 写真：原則使用しない

## 9. 未決定事項

- アプリ名
- ロゴ
- ブランドカラー
- 使用フォント
- デザインシステムの具体値
- 収支入力で扱う具体的な入力項目
- 収支カテゴリ
- ダッシュボードに表示する具体的な指標
- 月次レポートで表示する具体的な指標・グラフ
- 設定ページで変更可能な項目
- データ保存方式
- ユーザー認証の有無・方式
- 通貨・言語等の地域設定
- 各画面の具体的な文言
- 実際に使用する収支データ
- Mobileナビゲーションの具体的方式
- 単一の最重要ユーザー行動

## 10. 成功条件

- 収入・支出・残高・月ごとのお金の流れを把握しやすい
- できるだけ少ない操作で利用できる
- 情報量があっても把握しやすい
- 明確な視覚階層を持つ
- UI全体に一貫性がある
- 装飾過多にならない
- Desktop / Tablet / Mobileに対応する
- アクセシビリティを考慮する
- 確定したスコープから逸脱しない

客観的な完成判定は `09_ACCEPTANCE_CRITERIA.md` に従う。
